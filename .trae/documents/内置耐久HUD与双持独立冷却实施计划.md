# 内置耐久 HUD 与双持独立冷却实施计划

## Context

项目已经包含移动光源、剑格挡、飞轮冲刺、移动辅助等内置能力。现在新增两项可独立关闭的内置功能：

1. 在屏幕左侧中部显示六个装备/手持槽位的剩余耐久数字：头盔、胸甲、护腿、靴子、主手、副手。
2. 增加双手近战攻击机制，参考 Simply Dual Wielding，但主手和副手使用互不影响的独立冷却。

耐久 HUD 是纯客户端显示；双持攻击会改变战斗规则，必须由服务端权威判定，不能只在客户端触发伤害。

## 推荐范围与默认约定

### 耐久 HUD

- 新增独立客户端 HUD 类，沿用 `SwordBlockingHud` 与 `TimeHaloSkillHud` 的 `RenderGuiEvent.Post` 绘制模式。
- 以 GUI 缩放后的屏幕尺寸为坐标基准，六行默认整体锚定屏幕左侧并以屏幕垂直中心为中心排列。
- 增加可配置的自定义位置：水平位置使用距左侧的像素偏移，垂直位置使用相对屏幕垂直中心的像素偏移；位置按 GUI 缩放后的坐标计算，窗口尺寸和 GUI 缩放变化时仍保持相同的锚定关系。
- 使用 `EquipmentSlot.HEAD/CHEST/LEGS/FEET/MAINHAND/OFFHAND` 读取物品。
- 显示剩余耐久：`maxDamage - damageValue`；空槽、不可损坏物品不显示数字，但保留对应行位置，避免六个预设上下跳动。
- 沿用已有 HUD 的隐藏 GUI、打开界面、旁观模式和玩家为空时不绘制规则。
- 第一版只显示文字与轻量背景，不加入图标、拖拽布局和动画；位置通过配置调整，不做游戏内拖拽编辑器。

### 双持攻击

- 主手左键继续走原版攻击；副手使用独立、可重绑的客户端按键触发，避免与当前剑格挡、盾牌举盾和原版使用键直接冲突。
- 第一版只支持副手近战实体攻击，不扩展副手方块破坏、弓弩、食物、盾牌、三叉戟和其他远程物品的特殊行为。
- 客户端只发送“玩家请求使用主手/副手攻击”的意图；服务端重新检查功能开关、手持物、目标、距离、攻击状态和冷却后执行攻击。
- 主手和副手分别维护服务端攻击冷却，不能复用或互相重置原版共享的 `getAttackStrengthScale()` / `resetAttackStrengthTicker()`。
- 每只手的冷却按该手当前近战物品的攻击速度计算；冷却状态按手位保留，切换物品不会直接重置冷却，避免快速切换绕过 CD。死亡或重新加入后按服务器运行时状态重新初始化。
- 第一版复用原版攻击距离、暴击判定、击退和伤害事件链；副手攻击会以真实玩家作为伤害来源，尽量兼容现有附魔与武器特效。对明确依赖主手读取的现有能力（例如部分 Dawn 逻辑）先记录兼容限制，再单独适配。
- 服务器配置关闭双持后，服务端拒绝副手攻击请求；客户端按键即使仍存在也不能绕过服务器开关。

## 耐久 HUD 实现

- 新增 `src/main/java/com/emberstar/endbounember/client/EquipmentDurabilityHud.java`。
- 订阅 `RenderGuiEvent.Post`，先检查客户端配置和 HUD 可见性条件。
- 读取六个 `ItemStack`，使用运行时 `getMaxDamage()`，兼容项目已有的最大耐久修改 Mixin。
- 以屏幕左边距、六行行高和整体垂直中心计算坐标；数值使用统一右对齐，避免一位数、三位数切换导致布局抖动。
- 使用翻译键提供槽位名称，避免硬编码中文；颜色可先统一为白色/浅灰色，耐久过低时使用固定的警示色。

## 双持实现

### 客户端输入与网络

- 新增客户端按键注册类，使用 `RegisterKeyMappingsEvent` 注册“副手攻击”按键，默认值采用不占用原版核心操作的按键，并允许玩家在按键设置中重绑。
- 新增 C2S 双持攻击请求 payload，内容只包含攻击手位；在 `EndboundEmber` 注册 payload。
- 按键触发时发送请求，不直接在客户端执行服务端伤害；本地只负责攻击动画/反馈所需的最小表现。

### 服务端战斗与独立冷却

- 新增双持服务端处理类，按玩家维护主手和副手两个冷却状态。
- 服务端处理请求时：
  1. 检查 `DUAL_WIELD_ENABLED`。
  2. 检查请求手中的物品是否为可近战攻击物品。
  3. 通过玩家当前视线和原版实体攻击范围确定目标，不接受客户端提交的任意目标或伤害值。
  4. 检查该手冷却是否结束。
  5. 执行攻击并只更新对应手的冷却。
- 新增客户端 Mixin 或输入拦截时，尽量只处理副手按键，不改写原版主手 `startAttack` 流程；将 Mixin 放入 `endbound_ember.mixins.json` 的 `client` 列表。
- 对双持与 `SwordBlocking`、盾牌使用、DoomPillar 模拟攻击的交互做专项验证，避免副手攻击误取消原版物品使用或影响主手冷却。

## 兼容性边界

- 不把双持实现为简单的 `LivingHurtEvent` 伤害复制，因为该方式无法可靠区分攻击手，也不能正确处理攻击范围、冷却、击退、暴击和服务端权威。
- 不允许客户端自行决定伤害、目标或冷却完成状态。
- 第一版不承诺所有第三方武器和附魔的副手专属效果都自动兼容；先确保原版近战物品、普通实体目标和本模组基础伤害事件链正常。
- 如果发现某个本模组效果固定从主手取物，将在对应逻辑中补充攻击手上下文，而不是通过全局切换主手物品绕过。

## 实施顺序

1. 增加 COMMON/CLIENT 配置规格及语言键。
2. 实现六行耐久 HUD，完成不同 GUI 缩放、空槽、不可损坏物品和低耐久显示验证。
3. 注册副手攻击按键与 C2S payload。
4. 实现服务端主副手独立冷却和近战实体攻击。
5. 接入客户端输入拦截与必要 Mixin，验证主手原版行为不回归。
6. 处理格挡、盾牌、武器切换、死亡/重连、单人集成服务器和专用服务器场景。
7. 运行构建、`git diff --check`，并进行游戏内实测。

## 验证标准

- 配置关闭耐久 HUD 后，客户端不绘制六行数字；开启后在不同 GUI 缩放和分辨率下位置稳定。
- 六个槽位显示的是剩余耐久，装备更换后实时更新，满耐久、空槽和不可损坏物品行为符合约定。
- 主手连续攻击仍保持原版行为；副手按键能攻击当前合法目标。
- 主手攻击不会重置副手 CD，副手攻击不会重置主手 CD；两手可以按各自 CD 独立交替攻击。
- 双持配置关闭时，服务端不执行副手攻击。
- 不会因客户端伪造目标、伤害或冷却而绕过服务端检查。
- 剑格挡、盾牌举盾、方块破坏、远程物品使用和已有内置技能不出现明显回归。

## 待用户确认的默认点

实施前若需要调整，优先确认以下约定：

1. 副手攻击是否接受“独立可重绑按键”方案，还是必须采用鼠标右键/其他固定输入。
2. 副手是否只允许剑、斧等近战物品，还是允许所有带近战攻击属性的物品。
3. 副手伤害是否完全沿用物品自身伤害，还是需要像部分双持模组一样设置伤害折减。
4. 无耐久物品对应行是否保留槽位名称，当前计划为保留行但隐藏数字。
