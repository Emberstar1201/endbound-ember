# 祛魔台视觉改版实施计划

## Context

用户反馈目前祛魔台界面是灰底手绘槽框，观感粗糙；方块模型仍直接使用原版附魔台顶部和侧面纹理。用户希望 GUI 尽量直接采用此前指定的 Cursee-Development/Dis-Enchanting-Table 1.21.1 上游视觉。用户确认方块本体采用上游矮台造型。

上游 GUI 纹理为单结果槽设计，而本项目保留 3 个输入槽和最多 27 本独立附魔书输出。因此复用上游美术主题并扩展布局，使纹理匹配现有多结果槽，不将上游单结果菜单照搬进来。

## 实施方案

1. 获取并核对 1.21.1 上游 GUI 背景 PNG、矮台模型和方块专属纹理，确认资源出处、原始像素尺寸与布局。以 GUI 原图为美术基础，扩展/重排成适配本项目 9×3 输出格、三个输入格和玩家背包的背景；保留上游羊皮纸、书卷与深紫色魔法面板主题。新增资源放入本模组 assets 命名空间，不改动用户上传文件。
2. 更新 `ModClientEvents.java` 的 `DisenchantmentTableScreen`：以背景纹理替换现有灰色填充、手绘槽框；依据实际背景坐标核对 `imageWidth`、`imageHeight`、菜单槽位、标题和玩家背包标签。维持槽位和菜单规则，仅调整必要的屏幕尺寸/槽位坐标以准确对齐纹理。
3. 更新祛魔台方块模型为上游矮台外形，替换原版附魔台顶/侧纹理为专属主题贴图；同步检查方块状态、物品模型和掉落表的模型引用。模型保持静态，不新增不必要的方块实体渲染器。
4. 保持 `DisenchantmentTableMenu.java` 的行为不变：每个可提取的非诅咒附魔各输出一本书，诅咒留在原物品，材料成本、领取规则和物品保存逻辑不因美术调整改变。
5. 更新 `THIRD-PARTY-NOTICES.md`、`README.md`、`README_EN.md`：如实注明直接采用/改编的上游 GUI 与方块美术、上游仓库及作者/组织和 Unlicense；区分上游原始资源与本项目改编资源，保留项目自身 GPLv3 代码和 CC BY 4.0 自制美术声明，不错误声称上游资源为本项目原创。

## 验证

- 运行 Gradle build，检查资源 PNG、模型 JSON 与纹理引用。
- 在客户端打开界面，检查不同窗口尺寸下背景、3 个输入槽、9×3 结果槽、背包和快捷栏的对齐、无裁切/遮挡，确认物品图标、悬停提示正常。
- 放置、持有、破坏祛魔台，检查方块外观、物品栏模型与掉落模型一致地使用矮台和专属纹理。
- 验证多个附魔仍分别显示并领取；诅咒、书和青金石消耗及现有结算规则保持不变。
- 使用上游材料时复核来源与许可声明准确；不提交 Git commit。
