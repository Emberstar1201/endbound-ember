# 村民与少女劫掠防卫、愚者刷新及铁砧机制

## Context

用户明确了实现顺序：先让驯服与未驯服的三类少女主动攻击灾厄村民；再修正村庄自然村民大量无业；调整愚者刷新；最后调整铁砧。已确认主要问题是定时职业重置会排除村民记忆中的有效工作站，导致即使村民仍有唯一工作站也被误判失业。原版 NITWIT 应直接使用现有愚者交易逻辑和原版模型。

## 实施方案

1. **少女主动攻击灾厄村民**：扩展三类少女共用的敌对实体标签，添加原版 `#minecraft:raiders`，使驯服及未驯服的丧尸娘、溺尸娘、幸存者少女都能主动锁定劫掠者类别。保留现有主人助战、亡灵目标、同类与受保护女仆白名单。
2. **修正自然村民过多无业**：在 `BetterVillagerTrading` 的周期性职业重置中，先确认 `JOB_SITE` 指向的工作站仍存在且与当前职业匹配；有效则保留职业。仅当自己的工作站失效且周围没有替代工作站时，才按原设计重置。工作站破坏事件只处理记忆指向本次被破坏位置的村民，避免误清除周围其他村民的职业、交易和等级。
3. **调整愚者刷新/接入**：原版 `NITWIT` 村民统一标记为愚者，复用现有愚者交易与自动补货，继续使用原版傻子村民模型，不新增实体或模型。普通无业村民转为愚者的自然概率维持当前极低值 `0.0001`，不擅自提高稀有刷新率；实现中避免重载时重复初始化。
4. **铁砧机制**：新增专用 `AnvilMenu` Mixin。通过结果有效性检查后再将纯改名费用显示/结算为 0，避免原版因费用为 0 清空结果；取消 40 级“过于昂贵”导致的结果清空；修理与附魔合成费用保持原版逻辑。保留 `CommonHooks.onAnvilRepair` 调用并将最终损耗概率缩放为原值的 5%。注册到 `endbound_ember.mixins.json`。

## 验证

1. 执行 `gradlew compileJava` 并检查 Mixin 配置加载。
2. 游戏内分别验证三类少女在驯服/未驯服状态下均主动攻击灾厄村民；确认同类、受保护女仆和主人助战行为不回退。
3. 验证只有唯一有效工作站的村民不会变无业；工作站确实被破坏且没有替代站时才重置；大师级保护不变。
4. 验证原版傻子村民使用原版模型并获得愚者交易、自动补货；无业村民转愚者仍保持极低概率。
5. 验证铁砧改名显示与实际扣费均为 0，40 级以上结果仍可取出；修理/附魔操作仍收费，铁砧损耗显著降低。
