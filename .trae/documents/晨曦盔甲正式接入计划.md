# Context

当前仓库已有晨曦模板、晨曦物品图标和盔甲穿戴层纹理，但晨曦盔甲尚未注册、未加入创造物品栏，也没有对应锻造配方。目标是把晨曦盔甲作为正式四件套接入，同时不引用路径中的盔甲展开图资源。

已确认需求：

- 四件装备分别由对应铁甲、晨曦模板 `endbound_ember:dawn_template`、铁锭在锻造台升级获得。
- 每件基础耐久为 2500；现有耐久强化 II 的最大耐久倍率机制继续生效。
- 全套合计护甲值 25、盔甲韧性 25、击退抗性 1.0。
- 每件同时带保护、火焰保护、弹射物保护、爆炸保护 III，以及自定义耐久强化 II。
- 掉落物免疫火焰、岩浆和仙人掌销毁。

# 实施方案

1. 在 `ModArmorMaterials.java` 新增晨曦盔甲材质，使用已有 `dawn_layer_1` 与 `dawn_layer_2` 穿戴层资源，不引用盔甲展开图。护甲值按铁甲比例取整为头盔 3、胸甲 10、护腿 8、靴子 4，总计 25；盔甲韧性分配为 6、7、6、6，总计 25；击退抗性四件各分配 0.25，总计 1.0。
2. 在 `EndboundEmber.java` 注册 `dawn_helmet`、`dawn_chestplate`、`dawn_leggings`、`dawn_boots`，每件使用 `.durability(2500).fireResistant()`，并加入现有物品创造物品栏。
3. 新增四个物品模型 JSON，仅引用已有 `textures/item/dawn_helmet.png`、`dawn_chestplate.png`、`dawn_leggings.png`、`dawn_boots.png`，不引用盔甲展开图。
4. 新增四个 `minecraft:smithing_transform` 配方，模板为晨曦模板、基础为对应铁甲、添加物为铁锭、结果为对应晨曦盔甲。
5. 为锻造结果写入五种固定附魔：原版保护、火焰保护、弹射物保护、爆炸保护均为 III，自定义耐久强化为 II。优先验证配方结果组件能否保留互斥保护附魔；若数据配方不能稳定生成该组合，则在专用锻造结果路径中写入组件，避免影响其他配方。
6. 添加仅针对晨曦盔甲掉落物的保护逻辑：`fireResistant()` 负责火焰和岩浆，仙人掌伤害单独在窄范围的物品实体伤害处理处拦截，不能修改全局仙人掌伤害行为。
7. 在四份语言文件中补充四件物品名称，避免创造栏或锻造结果显示原始键名。

# 验证

- 运行 NeoForge 编译任务，确认 Java、资源模型和配方均通过加载。
- 在游戏中确认四件装备出现在创造物品栏，物品图标来自 item 图标资源。
- 分别验证四种铁甲升级配方、五种固定附魔和基础耐久 2500。
- 穿齐装备后检查护甲值 25、盔甲韧性 25、击退抗性 1.0。
- 检查耐久强化 II 会在现有机制下继续增加最大耐久。
- 将四件装备掉落到火焰、岩浆、仙人掌中，确认均不会销毁；同时确认普通物品行为不变。
