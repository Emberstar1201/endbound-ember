# 重置版时序锚点替换与兼容性调整

## Context

用户提供了重置版时序锚点结构文件 `qqqq.nbt`，需要替换工程现有的 `chrono_anchor.nbt`，并判断现有放置逻辑是否需要重写。经检查，新 NBT 可正常读取，尺寸为 25×82×25，包含已注册的展示台/石英展示台方块实体及一个物品实体；现有 Java 放置流程按模板实际尺寸工作，因此不需要整体重写。

用户已确认：新版建筑应生成在时间乱流维度出生点旁，而不是强行以出生点为中心。

## 推荐实现

1. 将用户上传的 NBT 复制并替换为源资源：
   `src/main/resources/data/endbound_ember/structures/chrono_anchor.nbt`
2. 更新 `TimeTurbulenceLevels.java` 中仍然描述旧结构尺寸的注释，改为按模板实际尺寸说明。
3. 重新设计 `CHRONO_ANCHOR_OFFSETS`，按 25×25 底面为建筑预留空间，保持建筑位于出生点旁，并保证玩家出生落脚区不被结构占用。优先使用少量互不重叠的候选点，不改变结构朝向。
4. 暂时保留 `CHRONO_ANCHOR_Y_OFFSET = -2`，因为仅凭 NBT 无法确认新版建筑底部与 y=16 石英地板的设计标高；通过测试维度确认底层是否需要埋入地基后再调整。
5. 保留基于 `template.getSize()` 的区块加载、占用检查和结构放置逻辑；保留 `BlockIgnoreProcessor.STRUCTURE_AND_AIR`。不新增结构分片或固定尺寸逻辑。
6. 不清除或迁移 `ChronoAnchorSavedData`。已有维度若 `Placed=true`，继续保留原建筑，避免替换资源后覆盖玩家改造；新结构只对尚未放置的维度生效。
7. 暂不修改展示台 Java、注册、模型或方块实体序列化。新 NBT 使用的展示台类型和 `DisplayItem`/`RitualType` 数据与现有实现兼容；放置后重点验证方块实体物品显示及物品实体是否产生预期效果。
8. 现有 `chrono_anchor.json` 战利品表仅在结构包含箱子且结构逻辑引用它时才有意义。新版不含箱子，先不删除或改写该资源，避免扩大无关改动。

## 关键文件

- `src/main/resources/data/endbound_ember/structures/chrono_anchor.nbt`
- `src/main/java/com/emberstar/endbounember/world/TimeTurbulenceLevels.java`
- `src/main/java/com/emberstar/endbounember/world/ChronoAnchorSavedData.java`（仅验证旧存档策略，不预期修改）
- `src/main/java/com/emberstar/endbounember/block/DisplayPedestalBlockEntity.java`（仅验证 NBT 字段兼容）
- `src/main/java/com/emberstar/endbounember/EndboundEmber.java`（仅验证方块/方块实体注册）

## 验证

1. 构建前检查新 NBT 的尺寸、方块 ID、方块实体 ID 与结构实体记录。
2. 执行 `./gradlew.bat compileJava --console=plain -q`，确认代码与资源处理通过。
3. 执行 `./gradlew.bat build --console=plain -q`，确认最终 jar 包含替换后的 `chrono_anchor.nbt`。
4. 在新存档中进入时间乱流维度，确认建筑位于出生点旁、未覆盖玩家落脚区，底层与石英地板高度正确，入口/顶部结构完整。
5. 检查 5 个展示台的物品、仪式数据和客户端渲染；检查 NBT 中的物品实体是否正确生成且不会造成意外掉落或重复生成。
6. 在已有已放置锚点的存档中确认不会因替换资源自动生成第二座或覆盖旧建筑。
7. 若实测发现底层标高不对，只调整 `CHRONO_ANCHOR_Y_OFFSET`；若候选点仍与出生区冲突，只调整 `CHRONO_ANCHOR_OFFSETS`，不重写模板加载与放置流程。
