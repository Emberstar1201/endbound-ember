# 双持与三项体验修复实施计划

## 背景与目标

继续完成已批准的双持攻击优化，并一并处理三项体验问题：飞轮冲刺期间饥饿/饱和消耗异常、清理砂轮优化残留、拂晓能量满时阻止剑格挡。保持祛魔台及其配置、方块、菜单和语言资源不变。用户已确认：满能量时的格挡限制持续到拂晓能量消耗后立即解除。

## 实施步骤

1. **完成双持攻击与反馈**
   - 保留 `DualWieldCombat.hasMatchingDualWeapon` 的规则：双手是同一 Item 且两手属性组件均声明攻击伤害，以支持使用标准 `ItemAttributeModifiers` 的其他武器模组。
   - 右键只在双手匹配、准星命中有效实体时拦截；不匹配或没有有效目标时放行原版使用。V 键保留备用入口。服务端持续自行校验目标、射程、遮挡、队伍伤害规则及匹配武器条件。
   - 修正副手攻击伤害/攻速对属性修饰符的读取，按物品组件提供的标准计算方式与槽位适用性处理；保留独立副手冷却，不改主手冷却。依据已确认规则，合法目标攻击尝试即使被原版受击无敌帧挡下也消耗副手冷却。ww增服务端冷却状态同步及客户端 HUD；玩家死亡、换世界、重连或武器不匹配时清理/隐藏状态。
   - 简化不再有服务端语义的攻击请求字段，保持客户端请求不能绕过服务端校验。

2. **抑制飞轮冲刺引发的异常饥饿消耗**
   - `FlywheelDash` 没有显式扣食；冲刺速度和位移可能令原版移动/疾跑疲劳快速累积。
   - 先在 NeoForge 1.21.1 现有事件/API 中选择仅针对飞轮主动位移期间的耗尽抑制点；只消除冲刺本身额外造成的疲劳，不直接改食物等级/饱和度，也不削弱正常疾跑、普通移动、攻击或其他系统的消耗。
   - 仍保留冲刺期间发生的其他独立耗尽来源；若无法精确区分移动耗尽与同 tick 其他来源，则采用最窄作用域并以运行验证确认。

3. **移除砂轮改动说明，保留祛魔台**
   - 当前源码与游戏语言资源中未发现砂轮配置、逻辑或语言键；旧砂轮 Mixin 已处于删除状态。
   - 仅从 `README.md`、`README_EN.md` 清除砂轮优化介绍及对应版本说明；除非进一步发现确切砂轮专属条目，不改祛魔台、铁砧配置/逻辑/语言内容。保留工作区中用户已有的其他变更。

4. **满拂晓能量时暂时阻止剑格挡**
   - 在 `DawnEnchantment` 提供必要的公共满能量查询方法（复用 `MAX_ENERGY` 和现有持久数据读取），并在 `SwordBlocking.onRightClickItem` 开始格挡前检查。
   - 满能量时阻止格挡，直到释放技能、能量重置后即恢复；不引入额外计时器。只影响拥有有效拂晓成长、且满能量的玩家，不改变祛魔台或其他玩家的格挡行为。

5. **验证与回归**
   - 执行 `.[0m\gradlew.bat build`（Windows 项目构建命令）和 `git diff --check`。
   - 检查双同武器（包括标准属性组件模组武器）、不同物品、普通右键、盾牌/剑格挡、目标遮挡/队友、冷却与冷却 HUD。
   - 比较飞轮冲刺前后食物等级、饱和度和耗尽值，并确认正常疾跑等消耗不受影响。
   - 检查满拂晓能量时格挡被拦截、能量消耗后恢复；确认 README 不再提砂轮，祛魔台文件与功能仍在。
