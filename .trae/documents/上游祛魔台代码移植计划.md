# 上游祛魔台代码移植计划

## Context

本项目已实现独立祛魔台，但目前菜单结算与 GUI 为自制实现，且游戏内视觉及 Shift-click 结算仍需验证。用户希望直接采用社区祛魔台实现并明确署名，现指定上游为 [Cursee-Development/Dis-Enchanting-Table 的 1.21.1 分支](https://github.com/Cursee-Development/Dis-Enchanting-Table/tree/1.21.1?tab=License-1-ov-file)，与项目的 Minecraft 版本相符。

目标行为已经明确：把物品上所有可提取附魔拆成多本附魔书，每个附魔单独一本；例如物品有三个可提取附魔，就输出三本书。诅咒保留在原物品上。每次处理整个物品时，普通书与青金石各消耗一个，不消耗经验或耐久。上游 1.21.1 的现成菜单是单结果槽、按一次操作产生一本合并附魔书，且其结算/成本规则不同，因此只能借鉴其实现结构与资源，不能直接照搬其单书结算逻辑。

上游仓库许可证为 Unlicense；本项目 README 声明项目代码采用 GPLv3、自制美术资源采用 CC BY 4.0，不能把两边说成同一许可。移植时保留本项目既有许可声明，并按实际采纳的代码/资源补充上游来源、署名和许可说明。

## 实施方案

1. 核对上游 1.21.1 分支的 `LICENSE`、作者/版权信息及拟采用实现与资源。重点查看 `DisenchantingTableMenu.java`、`DisenchantingMenu.java`、`DisenchantingTableScreen.java`、`DisenchantingMenuScreen.java`、`DisenchantingTableBlock.java`、`DisenchantingTableBlockEntity.java`、`DisenchantmentHelper.java`，以及 GUI、方块纹理和相关模型资源。只移植祛魔台所需内容，不照搬多平台启动与注册架构。
2. 保留本项目 NeoForge 注册体系，以比较后的上游实现替换/适配现有祛魔台方块、方块实体和菜单逻辑。核心结果改为“每个非诅咒附魔各生成一本独立附魔书”，即三个可提取附魔对应三本书；诅咒留在原物品。一次批量处理整个物品时，普通书和青金石各消耗一个，不消耗经验或耐久。结果区域须支持多个独立输出，不得把多个附魔重新合并成一本书；结果数量随可提取附魔数变化，领取不能吞失未取出的书。
3. 迁移上游 GUI 实现及确有必要的贴图/方块资源，调整命名空间和路径，并复用本项目现有方块、方块实体、菜单注册。将单结果槽界面调整为可清楚区分多本输出书的结果区域；确保输出数量变化、玩家背包已满、关闭界面、Shift-click 等情况下物品安全。删除被替代的临时手绘 GUI 代码，避免引入重复实现。
4. 在 `README.md` 与 `README_EN.md` 增加上游项目链接、作者/项目署名、明确说明直接使用或改编了哪些代码/资源，并注明上游 Unlicense；不改变本项目 GPLv3 与自制美术 CC BY 4.0 的现有说明。
5. 检查差异，运行 Gradle Java 编译及资源 JSON/引用检查；在可用开发客户端验证多个非诅咒附魔分别生成多本书、诅咒保留、整批材料仅扣普通书和青金石各一个、无经验/耐久消耗、GUI 多结果展示、普通领取与 Shift-click、物品保存/掉落等关键路径。
