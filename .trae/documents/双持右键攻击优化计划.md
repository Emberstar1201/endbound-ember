# 双持右键攻击优化计划

## Context

用户预期在双手装备同类武器（例如双剑、双斧）时按右键执行攻击，但当前右键由 `SwordBlocking.onRightClickItem` 处理并进入格挡。静态调查发现双持攻击现有入口是客户端 `V` 键发送 `DualWieldAttackPayload`，服务端调用 `DualWieldCombat.attackOffhand`；它没有监听鼠标右键。剑格挡监听器在配置关闭时会立即返回，因此关闭格挡不会让双持攻击自动绑定到右键。

## 推荐实施方式

1. 明确右键攻击具体要攻击哪只手，以及“同类武器”按同一物品 ID 判断还是按剑/斧等武器类别判断；同时确认原有右键使用行为与 `V` 键副手攻击是否保留。
2. 在客户端右键输入路径加入条件判断：仅在双持开关开启且两手满足确认后的武器匹配条件时，抑制剑格挡/普通右键使用并发送专用攻击请求；否则保留原有行为。
3. 服务端在现有 `DualWieldCombat` 攻击管线中按确认的手别选择武器、冷却及伤害，并继续验证武器有效性和攻击目标；避免仅依赖客户端条件。
4. 保持 `V` 键既有行为（除非用户明确要求替换），并确保剑格挡关闭时条件攻击路径仍独立于格挡配置。

## 关键文件

- `src/main/java/com/emberstar/endbounember/client/DualWieldClient.java`：现有副手攻击按键入口。
- `src/main/java/com/emberstar/endbounember/world/DualWieldCombat.java`：现有服务端目标选择、独立冷却和伤害实现。
- `src/main/java/com/emberstar/endbounember/network/DualWieldAttackPayload.java`：客户端至服务端攻击包。
- `src/main/java/com/emberstar/endbounember/world/SwordBlocking.java`：右键格挡处理，当前格挡开关关闭即返回。
- `src/main/java/com/emberstar/endbounember/Config.java`：双持与格挡配置开关。

## 验证

- 构建项目：`./gradlew.bat build`。
- 手动进入游戏验证：双手同类武器时右键攻击符合确认的手别与冷却；不同类或单手持武器时右键仍按原版使用；格挡开关开启/关闭均不导致错误拦截；`V` 键原行为保持。
- 检查网络包服务端校验和主副手冷却不互相覆盖。

## 待确认

用户说的“右手攻击”需要确定是否指主手（通常为屏幕右手）攻击，还是希望借右键触发副手攻击；“相同的武器”需要确定是相同物品 ID，还是同类武器（双剑、双斧均适用）。
