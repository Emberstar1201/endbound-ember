# 副手冷却按武器攻速同步修复计划

## Context

目前副手攻击冷却在测试中表现为不同武器冷却时长相同，且快捷栏样式的填充动画可能早于服务端实际可再次攻击时完成，造成冷却已结束的误判。本次调整应以服务端判定的武器攻速冷却为唯一依据，并让客户端动画严格显示同一冷却周期。

## 推荐方案

1. 检查 `DualWieldCombat.cooldownTicks` 当前对攻击速度修饰符的求值方式。确认武器修饰符的装备槽适用性，正确按副手武器本身的攻击速度计算冷却 tick（20 / 攻速，向上取整，至少 1 tick），避免因主手/副手槽不匹配而退化为统一默认攻速。
2. 在 `attackOffhand` 中每次攻击只计算一次冷却长度，并将其用于攻击间隔校验、冷却结束时间、总时长和首次同步包，确保服务端接受攻击的时间与 HUD 分母一致。
3. 检查周期性 S2C 同步及客户端插值的时间基准；修正任何会令进度提前完成的偏差。快捷栏和准星 HUD 均继续消费同一客户端进度，不另建计时逻辑。
4. 评估换武器时上一把武器的冷却时间戳是否导致新武器被额外限制；修改仅限于实现按当前武器攻速冷却所必需的范围。

## 关键文件

- `src/main/java/com/emberstar/endbounember/world/DualWieldCombat.java`：服务端冷却时长、攻击间隔及S2C同步。
- `src/main/java/com/emberstar/endbounember/network/DualWieldCooldownPayload.java`：检查现有剩余时间/总时长数据是否足以表达服务端冷却，无需变更则保持协议不动。
- `src/main/java/com/emberstar/endbounember/client/DualWieldCooldownClient.java`：冷却进度插值与归零状态。
- `src/main/java/com/emberstar/endbounember/client/DualWieldCooldownHud.java`：确认快捷栏填充使用统一进度，避免叠加本地计时。

## 验证

- 编译项目。
- 双持至少两种攻击速度不同的同类武器，记录副手攻击间隔，确认按武器属性对应的 tick 数计算，而非固定间隔。
- 使用快捷栏样式观察填充动画，确认填充耗时覆盖完整服务端冷却，动画完成后才可再次攻击。
- 检查准星样式、周期同步、冷却结束归零及冷却期间切换武器，确认显示和服务端限制一致。
