# 背景

用户测试发现两项体验与预期不符：攻击指示器切换到快捷栏模式时，副手冷却图标没有出现在副手槽旁；同时「基岩走搭」实际表现不像预期的基岩版搭路。目标是先修正 HUD 锚点与水平镜像，并收敛走搭目标选择，使其在游戏中表现稳定、操作含义清晰。

# 实施方案

1. **修正副手冷却 HUD**
   - 修改 `src/main/java/com/emberstar/endbounember/client/DualWieldCooldownHud.java` 的 `renderHotbarIndicator`。
   - 依据原版快捷栏副手槽真实位置确定 HUD 锚点，让图标显示在副手槽旁，而不是快捷栏另一端/主手位置；按左右主手布局分别验证。
   - 去除当前 `scale(-1, -1)` 的双轴翻转，改为仅水平翻转。背景和进度条共享正确锚点，保持垂直方向及高度不变。

2. **修正基岩走搭目标判定**
   - 修改 `src/main/java/com/emberstar/endbounember/client/BridgeAndWallJumpClient.java` 中的空中放置逻辑，并视实际文案同步 `Config.java` 与 `zh_cn.json` 等语言文件。
   - 将当前基于视线反向固定偏移、准星必须 MISS、遍历首个支撑块的估算逻辑替换为依据玩家脚下/移动方向选择候选落块位置，并按合法方块接触面构造原版放置交互。
   - 保留原版 `useItemOn` 服务端校验与物品消耗；仅在合法候选上尝试放置，放置失败不播放成功挥手反馈。
   - 当前按常见的「倒退搭桥：按住使用键，玩家倒退移动时向身后/脚下连续铺块」作为默认语义。若用户所说的基岩版搭法特指蹲搭、侧搭或不同输入，该默认方案需先调整再实现。

# 验证

- 执行 `./gradlew.bat build` 与 `git diff --check`。
- 游戏内检查快捷栏模式下副手图标贴近真实副手槽、仅水平镜像，覆盖左右主手及不同界面尺寸。
- 游戏内测试倒退搭桥、侧移转向、跳跃/下落、不同方块形状、方块耗尽及服务端拒放；确认目标格稳定、不会放入玩家内部或桥面上方，失败时不误播成功反馈。
