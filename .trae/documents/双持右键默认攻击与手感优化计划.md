# 双持右键默认攻击与手感优化计划

## Context

当前副手攻击的主入口仍是 V 键，右键双持分支已经能发起副手攻击，但手感反馈不一致：客户端在发送请求前先挥动副手，服务端成功后又广播一次挥动；即使攻击被冷却、无目标或判定失败，客户端也会先播放空挥。用户希望右键成为默认副手攻击输入，并且仅当主副手是相同武器时拦截剑格挡。

## 实施方案

1. **统一武器匹配语义**：在 `DualWieldCombat.hasMatchingDualWeapon` 中将当前“同属剑标签/斧标签”调整为同一物品类型（Item identity），同时保留剑/斧类别限制。相同物品不同耐久、附魔或名称仍匹配；不同物品但同为剑/斧不匹配。
2. **将右键作为默认入口**：在客户端 `DualWieldClient.onInteractionKey` 中，双持功能开启且主副手匹配时拦截主手 use 输入，发送要求服务端复核匹配状态的攻击包。匹配失败则不取消输入，确保原版使用与剑格挡正常工作。
3. **消除失败空挥与重复挥动**：移除客户端发送右键攻击包前的即时副手挥动，保留 `DualWieldCombat.attack` 中只在服务端伤害成功后执行的副手挥动。保留 V 备用键及其原有调用方式，不扩展其它输入改造。
4. **保留剑格挡职责**：`SwordBlocking.onRightClickItem` 继续只处理格挡，不自行处理双持攻击；格挡开关关闭时也不影响双持右键攻击。攻击包服务端校验保持现状。

## 涉及文件

- `src/main/java/com/emberstar/endbounember/client/DualWieldClient.java`：右键拦截与输入反馈。
- `src/main/java/com/emberstar/endbounember/world/DualWieldCombat.java`：同一武器判定；服务端成功攻击挥动保持唯一。
- `src/main/java/com/emberstar/endbounember/network/DualWieldAttackPayload.java`：复核现有服务端匹配与配置检查，不改变协议，除非实现中发现必要问题。
- `src/main/java/com/emberstar/endbounember/world/SwordBlocking.java`：确认格挡路径不再与双持攻击重复分派。

## 验证

- 执行 `./gradlew.bat build`。
- 游戏内检查：相同物品的双剑/双斧右键触发副手攻击；不同种类但同属剑/斧的组合不拦截右键；单手剑右键格挡保持原状；关闭剑格挡开关后，匹配双持仍可右键攻击。
- 检查无目标、冷却中和遮挡目标时不播放客户端预测空挥；命中成功时只出现一次副手挥动；V 备用键仍可用。

## 后续可选手感调优

- 若服务端确认挥动的网络延迟令人感觉迟缓，再评估客户端预测动画与服务端拒绝补偿；当前不加入预测以避免空挥及状态同步复杂度。
- 可将副手冷却与原版主手攻击速度/冷却反馈统一，便于玩家预判攻击节奏。
- 可继续校准副手攻击的目标选取、命中距离、遮挡和击退，使其更贴近原版攻击反馈。
