# 祛魔台界面与预览修复计划

## Context

用户反馈祛魔台 GUI 的玩家物品栏槽位与上方图案重叠，并且放入附魔武器与普通书后没有出现附魔书结果。当前屏幕将 176×166 的纹理置于高度 188 的面板顶部，而菜单背包槽从 y=84 开始，物品栏标题也位于 y=90，导致标签和槽位挤在一起。菜单的普通附魔装备产出逻辑本身会制作附魔书，且不检查经验；默认 25 点经验限制只作用于领取，因此不应把它作为空预览的修复方式，也不改变默认成本。

## 实施步骤

1. 对照 GUI 纹理确认玩家背包 3 行及快捷栏已对应纹理中的下方槽区，因此保留菜单中的 y=84/102/120 与 y=142，不搬动玩家物品坐标。
2. 在 `ModClientEvents` 中将屏幕尺寸改为纹理实际区域 176×166，按原纹理绘制，移除叠加到既有槽区的额外原版槽背景，调整物品栏标题至独立空白位置；保留上方操作槽坐标及纹理装饰。
3. 修正菜单预览的客户端更新：检查当前菜单槽位同步流程，确保服务端输入变化后新生成的 `previewContainer` 结果能通过菜单槽位同步到客户端；避免只依赖构造期间或客户端未触发的 `slotsChanged`。修复仅针对预览刷新/同步，不改变附魔装备的结算规则或经验门槛。
4. 修复多附魔书每次剥离的预览和结算一致性，使结果书与输入书留下的附魔符合既定剥离行为，并确保预览选择与提交使用同一附魔。

## 关键文件

- `src/main/java/com/emberstar/endbounember/menu/DisenchantmentTableMenu.java`：玩家槽位坐标、预览刷新/同步、附魔书拆分一致性。
- `src/main/java/com/emberstar/endbounember/client/ModClientEvents.java`：面板尺寸、槽背景绘制和物品栏标题位置。

## 验证

- 运行项目 Gradle 构建并执行 `git diff --check`。
- 客户端打开界面，确认标题不压住槽位、玩家背包与快捷栏完整落在预期底板中，顶部输入与结果槽位置不变。
- 生存模式放入附魔武器与普通书，确认结果预览显示；经验不足时仍显示但不可领取，经验足够时可领取，武器附魔被移除且普通书消耗一本。创造模式可用于快速验证结果槽显示和领取。
- 用含至少两种附魔的附魔书验证每次预览、取出的附魔和输入书剩余附魔一致。
