# 祛魔台上游整体重构实施计划

## Context

当前祛魔台是本项目自定义的 3 个输入槽、27 个结果槽和批量拆分附魔逻辑，与上游 `Cursee-Development/Dis-Enchanting-Table` 1.21.1 分支的实现并不一致。用户要求从根本上重写，直接套用上游仓库本身，因此本次以当前需求为最高优先级，取消此前“每个附魔单独生成一本书”的本地批量规则，改为上游的单结果槽、上游结算流程和上游成本行为。

上游代码、入口和注册体系不整体搬入，避免与本项目 NeoForge 注册体系和 Mod ID 冲突；只移植祛魔台相关的方块实体、菜单、结算辅助逻辑和客户端界面，并适配本项目现有注册对象。

## 目标行为

- 保留本项目现有注册 ID：`endbound_ember:disenchantment_table` 方块、方块实体和菜单，保证旧世界仍能识别原方块。
- 方块实体改为上游 3 格容器：附魔物品、普通书、单一结果槽。
- 菜单改为上游输入/输出槽结构及交互行为，包含普通附魔物、单附魔书、多附魔书的上游处理方式。
- 按上游实现处理普通书消耗、经验成本、附魔移除/保留和维修惩罚，不保留本项目旧的青金石消耗与 27 格批量领取规则。
- 保留服务端权威结算，确保普通点击、Shift-click、关闭菜单、背包满和重复点击不会复制或吞物品。

## 实施步骤

1. **移植并适配上游核心代码**
   - 对照上游 1.21.1 分支的祛魔台菜单、方块实体、结算辅助逻辑和 GUI，实现到本项目现有包结构。
   - 修改 `EndboundEmber.java` 中的菜单、方块实体注册引用，但保留现有注册名称和 `DeferredRegister` 体系。
   - 不引入上游 `@Mod` 入口、独立注册类、多加载器入口或无关功能。

2. **重写容器和菜单**
   - 替换 `block/DisenchantmentTableBlockEntity.java` 的 30 格 `SimpleContainer`，使用上游 3 格容器语义。
   - 替换 `menu/DisenchantmentTableMenu.java` 的 27 个预览/结果槽、青金石槽和批量结算代码，改成上游槽位、结果计算、材料消耗、经验处理和快速移动逻辑。
   - 保留方块坐标传输和距离校验，但使菜单创建流程与上游槽位契约一致。

3. **处理旧 30 格方块实体存档迁移**
   - 读取旧 `Items` 列表时，将槽 0、1、2 导入新的三个输入语义。
   - 将旧槽 3–29 的所有非空物品迁入独立的持久化恢复队列，不允许因容器缩容而截断。
   - 在恢复队列未清空前，菜单只允许逐项领取旧结果，暂停新的祛魔操作；队列需支持保存、重载、方块破坏和背包满场景。
   - 方块破坏时确保输入物品和恢复队列各掉落一次；正常新容器也不得重复掉落。
   - 对新格式增加迁移标记/队列字段，避免重复迁移或重复生成物品。

4. **适配方块交互和客户端界面**
   - 保留 `DisenchantmentTableBlock.java` 的方块交互入口和注册 ID，按新的容器生命周期处理破坏掉落。
   - 替换 `ModClientEvents.java` 中当前 27 格界面绘制逻辑，使用与上游单结果菜单匹配的屏幕布局和 GUI 资源。
   - 保留当前已采用的上游 GUI/矮台模型资源时，按新槽位重新确认纹理坐标；不再为旧 27 格布局保留专用绘制代码。
   - 核对方块模型、物品模型、方块状态、掉落表和语言键，确保新菜单和方块注册引用完整。

5. **更新来源与许可证说明**
   - 更新 `THIRD-PARTY-NOTICES.md`，明确列出实际移植/改编的上游代码、规则、GUI 和方块纹理，注明 Cursee Development、1.21.1 分支和 Unlicense。
   - 同步修改 `README.md`、`README_EN.md`，删除旧的“每个附魔一本书”和批量青金石规则描述，改为上游行为说明。
   - 保持本项目 GPLv3 代码和自制 CC BY 4.0 美术声明独立，不把上游 Unlicense 扩展到本项目原创内容。

## 验证方案

- 运行 `./gradlew.bat build`，确认 Java 编译、资源处理和打包通过。
- 启动开发客户端，确认旧方块 ID、方块实体 ID 和菜单 ID 均可注册，并能打开新界面。
- 分别测试普通附魔装备、单附魔书、多附魔书、诅咒附魔、经验不足、缺少普通书和背包已满场景。
- 测试普通领取、Shift-click、重复点击、关闭界面、区块重载和客户端重连，确认没有复制或吞物品。
- 构造旧 30 格方块实体 NBT，覆盖多个未领取结果物品，验证迁移队列可保存、重载、逐项取回和破坏掉落。
- 验证 JSON、模型引用、语言键、纹理引用和 `git diff --check`。
- 不创建 Git commit，保留工作区中与本任务无关的既有改动。
