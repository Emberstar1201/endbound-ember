# Context

“更好的附魔台”允许已附魔物品再次进入附魔流程，但现有候选过滤及兼容性处理可能导致重复候选、同级/低级附魔被再次应用；幸运附魔事件把原版三挡的零基索引误当作一基，导致第一挡不增强且第三挡费用上限错误。空挡位和无候选挡位还可能被误认为渲染故障。目标是在不替换原版界面、不重写附魔流程的前提下修正这几处逻辑，并保证菜单预览与实际点击规则一致。

# 实施方案

1. **修复同附魔兼容判断**
   - 修改 `src/main/java/com/emberstar/endbounember/mixin/EnchantmentCompatibilityMixin.java`。
   - 与原版保持一致：同一个附魔 Holder 不得与自身兼容；保留配置开启时不同原版附魔之间的兼容放宽，配置关闭时继续走原版逻辑。

2. **统一过滤候选及有效升级**
   - 修改 `src/main/java/com/emberstar/endbounember/enchantment/EnchantingTableRules.java` 的 `limitCandidates`，供菜单实际生成和 `EnchantmentPreviewEvents.computeRows` 共同复用。
   - 对重复候选按附魔身份去重，保留候选等级最高者；已有附魔只接受严格高于现有等级的候选，同级/低级不再消耗资源或更新种子。
   - 新增附魔受数量上限约束，并检查其与物品既有附魔及已接受候选的兼容性。达到上限时跳过该新增候选而非终止遍历，后续已有附魔的有效升级仍可保留。
   - 不实现同级合成升级、候选补抽或大规模附魔流程重构。

3. **修正三挡事件索引及费用单调性**
   - 修改 `src/main/java/com/emberstar/endbounember/enchantment/BetterLuckEnchantmentEvents.java`。
   - 档位使用原版索引 `0..2`，上限对应 `{13, 25, 30}`，第一挡能参与增强且第三挡不再被错误压到 25。
   - 保留原有触发概率、加成幅度和零费用不解锁规则；结果不得低于事件原值，避免覆盖此前其他事件处理器给出的更高值。
   - 修正文档注释，明确该事件调整菜单费用及候选生成输入。

4. **保留现有显示/同步机制**
   - 核对 `EnchantmentMenuMixin.java` 的候选过滤仍在原版线索生成和点击计算两处一致生效。
   - 核对 `EnchantmentPreviewEvents.java` 使用相同过滤结果；不强行显示空候选、也不制造可点击的伪线索。费用为零或最终候选为空时，挡位不可用属于有效状态。

# 验证

- 执行 `./gradlew.bat build` 与 `git diff --check`。
- 验证同一附魔不与自身兼容、不同原版附魔的既有兼容放宽仍有效。
- 验证已附魔物品只保留新增或严格升级候选；重复候选合并、容量边界不会丢弃后续可升级项。
- 验证三挡索引 0/1/2，费用为零不解锁，第三挡费用 30 不降低；保持预览、原版线索与点击后实际结果一致。
- 游戏内覆盖未附魔物品、已有附魔物品、书、不同书架数量及重复放入/取出场景；空候选时不得消耗经验或青金石。
